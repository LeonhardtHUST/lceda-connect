## 页面类型实测：仿真页 / 面板页

实测工程：`示例工程A`（example-team 名下），窗口 1283×722。该工程一次性覆盖四种设计：Board1（板）、Schematic1（原理图）、PCB1、Panel1（面板）、Simulation1（仿真）。

### 打开工程的窗口规则

双击工程树里的工程节点会**新建一个 page target**，不是复用当前窗口。

- `/json/list` 里出现两条 page：旧窗口 `<个人工程-01>`、新窗口 `示例工程A`
- 新窗口 URL 形如 `https://pro.lceda.cn/editor#id=<projectid>`
- 连接脚本的 `pick_page` 只按 URL 匹配，URL 里没有工程名，所以必须**按标题匹配**才能选中新窗口
- 打开工程后如果不切窗口，扫到的是旧窗口，会得出「什么都没变」的错误结论

### 打开设计后的 frame 结构

打开面板页后 frame 树从 2 层变成 4 层：

| frame | URL | 内容 |
|---|---|---|
| (main) | `https://pro.lceda.cn/editor` | 外壳：顶栏、面板、状态栏 |
| about:blank | `about:blank` | 空壳 |
| `frame_7bb7a828...@<工程UUID-02>` | `...?entry=panel` | 面板画布 718×399 |
| `frame_sheet-1` | `...?entry=panel` | 图页画布 1200×1200（SVG） |

- 命名规则：`frame_<hash>@<projectid>` 是主画布，`frame_sheet-<n>` 是图页
- `entry=panel` 是面板编辑器；原理图、PCB、仿真的取值要用 `frames` 现查，不要凭猜
- 设计内容在 SVG / canvas 里，DOM 拿不到元件与走线

### 仿真页

打开 `Simulation1` 后界面结构：

| 区域 | 内容 |
|---|---|
| 顶栏菜单 | 文件 编辑 视图 放置 设计 **仿真** 布局 |
| 第二行 | 常规工具 + 线宽/栅格（0.05 inch） |
| 第三行 | 仿真工具条，含 `瞬态分析` 按钮 |
| 左侧面板 | 图页树：main / 工程名 / Board1 / Schematic1 / PCB1 / Panel1 / Simulation1 / Ngspice1 |
| 中央 | 原理图画布 + 标题栏（图页名 Simulation1、A4、立创EDA） |
| 右侧面板 | 图页属性：基础属性（名称 Ngspice1、引擎 **NGSPICE**）、图纸边界 |
| 底部 | 器件 / 封装 / 复用模块 / 3D模型 / 面板库 / **仿真模型** / 立创商城 + 日志 / ERC |

`仿真` 菜单只有 5 项：**运行 / 暂停 / 停止 / 仿真设置 / 日志...**

操作路径：

1. 图页树里双击仿真页 → 画布出现原理图
2. 底部「仿真模型」库选模型（实测 90 条，如 脉冲电流源 Current Source(Pulse)、正交电流源 Current Source(AC)、时钟电流源 Current Source(Clock)）
3. `仿真` → `仿真设置` 或工具条 `瞬态分析` 设分析类型与参数
4. `仿真` → `运行`，`暂停`/`停止` 控制
5. `仿真` → `日志...` 或底部 `日志` 标签看结果

未验证：运行后波形窗口出现在哪个容器（底部标签还是新面板）。要下断言必须先跑一次仿真。

### 面板页

打开 `Panel1` 后：

- 画布是 iframe（`?entry=panel`），主画布 718×399，另有一张 1200×1200 的图页画布
- 外壳区域的元素比仿真页多（40 节点 vs 27），因为面板页有额外的图页标签与面板工具条
- 面板内容用 SVG 渲染，DOM 里只有 `svg` 节点，拿不到面板上的元件实例

### 对后续操作的直接影响

- 打开任何工程后，先 `pages()` 看有几个窗口，再按标题选中，否则会对着旧窗口操作
- 扫地图必须逐 frame 求值，只扫主窗口会漏掉整块画布
- 画布内的元素拿不到，操作只能靠工具栏按钮、菜单、面板属性表，或者键盘命令（见 `02-settings-shortcuts.md`）

## 页面类型实测（二）：原理图 / PCB / 元件

同一窗口 `示例工程A`。按能力条目记录，不再写「我点了哪里」。

### C4 状态：怎么知道现在在哪个编辑器

**顶部编辑器标签栏**才是页面切换入口，不是左侧图页树。

实测标签：`开始页 | Ngspice1 | Panel1 | P1.Schematic1 | PCB1`。点标签切换编辑器，图页树只是"选内容"，两者不是一回事。

**`entry=` 不能单独判类型**。实测：

| 打开的文档 | 新出现的 frame | entry 值 |
|---|---|---|
| Panel1（面板） | `frame_<hash>@<id>` + `frame_sheet-1` | `entry=panel` |
| Schematic1（原理图） | 无新增，复用上面两个 | `entry=panel` |
| PCB1（PCB） | `frame_4d9dc3a2...@<id>` | `entry=pcb` |

结论：`entry=panel` 是**图页渲染器**，同时服务面板和原理图；文档类型要看标签栏选中项或图页树选中项。只看 entry 会把原理图误判成面板。

**frame 会累积**。每换一次编辑器，旧 frame 不销毁，只是隐藏。所以 frame 数量不能当"打开了几个编辑器"用，扫描也必须只取可见 frame。

### C1 发现：菜单的一级与二级规则不同

| 动作 | 结果 |
|---|---|
| 点一级菜单 | 展开 |
| 点一级菜单里的"有子菜单"项 | **不展开**，必须悬停 |
| 悬停有子菜单的项 | 子菜单在右侧浮出 |

探测时有坑：同时存在父子两个弹层，取"最大/最上层"会拿回父菜单。正确做法是**取所有弹层，选 left 最大的那个**。

`文件 → 新建` 子菜单实测 18 项：工程(J)... / 板 / 原理图 / PCB(P) / 面板 / 仿真... / 器件... / 封装(Y)... / 3D模型(D)... / 仿真模型... / 图纸... / 网络标识... / 网络端口... / 跨页连接标识... / 无电气标识... / 复用模块... / 面板库...

快捷键表里只有 `新建 - 工程 = Shift+N`，新建器件**没有快捷键**，必须走菜单。这是 C1 的典型情况：发现路径只在菜单一条路上成立。

### 原理图页

- 左侧图页树会展开出 `Schematic1 → 图页: 1. P1`，说明原理图下面还有图页层级
- 画布同样是 iframe 内的 SVG/canvas，DOM 拿不到元件
- 工具栏第二行有 `常用(默认)` 下拉，是工具栏配置档，可切换

### PCB 页

打开后新增 `entry=pcb` 的 frame，画布为 canvas（截图里是深色板面）。

已确认的关键入口：

| 位置 | 内容 |
|---|---|
| 右侧面板 | 层管理器：1 顶层 / 3 顶层丝印 / 5 顶层阻焊 / 7 顶层锡膏 / 9 顶层装配 / 2 底层 / 4 / 6 / 8 / 10 / 11 板框层 / 12 多层 / 13 文档层，可切 全部、铜箔层、非铜层 |
| 顶部工具条 | 含 DRC 按钮，单位切 mil，栅格设置 |
| 底部标签 | 库 / 日志 / **器件标准化** / **DRC** / 查找结果 / 属性清单 |
| 底部器件表 | 列含 序号、器件、封装、值、供应商、制造商、**立创编号**、描述 |

`器件标准化` 和 `DRC` 都是底部标签，不是弹窗——这是 C1 的又一条路径：功能不一定在菜单里，也可能在底部标签条。

### 元件页

没有快捷键，只能 `文件 → 新建 → 器件...`（悬停展开子菜单后点 `器件...`）。

点开后出现「新建器件」对话框，实测字段：

| 字段 | 形式 |
|---|---|
| 归属 | 个人 / 团队下拉 + 当前账号，另有「创建团队」 |
| 器件 | 类型下拉（默认 `元件`）+ 名称输入框 |
| 分类 | 输入框 + 「管理分类」链接 |
| 描述 | 多行文本框 |
| 按钮 | 批量创建 / 保存 / 取消 |

本次点 `取消` 退出，**没有创建任何文件**，所以元件编辑器内部结构仍未验证。要验证必须真的创建一个器件（或打开已有符号），属于写操作，需要单独授权。

### 对通用能力的直接结论

1. **C2 定位**：弹层探测要按"最右侧/最下层"选，不能按面积或 z-index 排序，否则父子菜单会串
2. **C3 输入**：画布不可 DOM 点击这一点在三种页面上完全一致，键盘命令是唯一稳定的通用通道
3. **C4 状态**：判断当前编辑器靠标签栏文字 + 图页树选中项；frame 的 entry 只是渲染器类型
4. **C5 校验**：PCB 的 DRC 有独立底部标签，结果可读；器件标准化的立创编号在表格列里，也可读

## 新建工程与放置/设计菜单

### 新建工程的可复用流程

实测于 `示例工程A` 窗口内，最终得到工程 `agent-drill-rc50`。

| 步 | 动作 | 实测细节 |
|---|---|---|
| 1 | 发 `Shift+N` | 直接弹出「新建工程」，不用点菜单 |
| 2 | 读对话框 | 容器 `lc_modal`，628×314；字段见下表 |
| 3 | 填名称 | 点名称输入框 → `Ctrl+A` → `Input.insertText` |
| 4 | 保存 | 点「保存」按钮（按文字找，坐标会随窗口大小变） |
| 5 | 处理确认框 | 弹出「创建成功！是否打开新工程？」，含「在新窗口打开」勾选 + `是` / `否` |

「新建工程」对话框字段：

| 字段 | 形式 | 默认值 |
|---|---|---|
| 归属 | 个人 / example-account / 我的团队 / example-team / 创建团队 | 个人 |
| 工程 | 单行文本 | `New Project_<日期>_<时间>` |
| 模板 | 选择器 | 默认模板 |
| 简介 | 多行文本 | 空 |
| 按钮 | 保存 / 取消 | — |

新建后的默认模板自带四件设计：`Board1`（板）、`Schematic1`（含图页 `1. P1`）、`PCB1`、`Panel1`。所以「从零开始」实际是从一个带骨架的模板开始，不需要手工建图页。

### 这一路上的四个坑

1. **对话框里 `document.querySelector('.lc_modal').querySelector('input')` 会拿到隐藏的旧弹窗**，值恒为空。必须按可见性过滤（`getBoundingClientRect().width > 0`）再取。
2. **`Shift+N` 必须带 `modifiers: 8`**，且 `rawKeyDown` 与 `keyUp` 成对发，否则不触发。
3. **确认框的「是」必须点**，否则工程建了但不打开，工程树里也不会出现新工程。
4. **打开新工程会替换原窗口**：实测新建后 page target 从「示例工程A + <个人工程-01>」变成「agent-drill-rc50 + <个人工程-01>」，原 2026 窗口消失。所以「打开工程前先记住有几个窗口」这件事不能靠数量，要按标题记。

### 放置菜单（25 项，原理图页）

`器件/复用模块(P)...` / `快捷器件(F)` / `导线(W)` / `总线(B)` / `网络标签(N)` / `短接标识(D)` / `网络标识(O)` / `网络端口(I)` / `跨页连接标识(V)` / `非连接标识(C)` / `连接点标识(J)` / `差分对标识(F)` / `测试点(T)` / `屏蔽区域` / `元件屏蔽` / `复用模块(S)` / 折线(L) / 圆弧(A) / 贝塞尔曲线(Z) / 圆形(U) / 椭圆(E) / 矩形(R) / 文本(T) / 图片(G)...

**括号里的字母就是快捷键键位**。例如 `放置 → 器件` 按 `P`，`放置 → 导线` 按 `W`。这是 C1 的关键结论：菜单文字自带发现路径，不需要另查快捷键表。

### 设计菜单（18 项，原理图页）

`更新/转换原理图到PCB` / `下单嘉立创Layout服务...` / `从PCB导入变更` / `生成/更新模块符号` / **设计规则...** / **检查DRC** / **分配位号...** / `PCB设计规则...` / `交叉选择...` / `交叉选择模式` / `布局传递...` / `网络类管理器...` / `差分对管理器...` / `等长网络组管理器...` / `更新工程库...` / `更新复用模块...` / `重置元件唯一ID...` / `工程设置...`

三个关键入口：

- `检查DRC`：原理图侧的 DRC（与 PCB 底部 DRC 标签不是同一个）
- `分配位号...`：给未编号元件批量分配 R1/C1 这类位号
- `更新/转换原理图到PCB`：原理图转 PCB 的桥

### 概念更正

**`库 → 器件` 表里的「立创编号」列 ≠ `器件标准化` 的分配功能。**

- 「库」面板是物料库浏览，表里显示的是该物料**本来就有**的编号，用于查询
- 「器件标准化」是底部独立标签，作用是把**当前设计里已有的器件**匹配到立创物料并写回编号

两者不要混：前者是查，后者是配。

- 原理图页的 frame 不新增，仍只用 `frame_sheet-1`，说明原理图和面板共用图页渲染器；`entry=` 不能判文档类型
- 画布放元件是否只能靠 `P` 键 + 坐标点击，还是能键入完整命令，未验证

## 「新工程打不开」的完整归因

### 结论：工程没坏，是窗口识别和加载时序的坑

新建的工程 id `<工程UUID-01>`，`dmt_Board.getAllBoardsInfo()` 回读到：

```json
{"boards":[{ "name":"Board1", "uuid":"ddec4491db76cb15",
  "pcb":{"name":"PCB1","uuid":"d3fa753091e78bc8"},
  "schematic":{"name":..., "page":[{"name":"P1","uuid":"ebd0c06803a821ba"}]} }]}
```

**Board1 / PCB1 / P1 都在**，工程是完整的。

### 四个叠加原因

#### 1. 双击前要先单击选中

只双击不选中时，行上的双键可能被当作"展开/无操作"。先单击（选中，行变 `tree-rowline-selected`）再双击，成功率高得多。

#### 2. 打开需要约 5 秒

实测双击后 `t+5s` 才在 target 列表里出现第 4 个 page。我在 3–6 秒时检查，得出"没打开"的结论——**太早**。

#### 3. 新窗口标题一开始不含工程名

刚打开时 `document.title` 是通用的：

```text
嘉立创EDA(专业版) - V4.1.78
```

加载完才变成：

```text
New Project_<timestamp> | 嘉立创EDA(专业版) - V4.1.78
```

我按标题过滤窗口（找 "usb_hub"/"agent-drill" 之外的新 page）时，把加载中的它漏掉了。**正确做法：按 url 里的 `#id=` 匹配，不要按标题。**

#### 4. 打开后停在开始页，没有活动文档

新窗口的标签只有 `图页 / 开始页 / 工程`，没有打开任何文档。

于是 `dmt_Board.getCurrentBoardInfo()` 抛：

```text
Cannot read properties of undefined (reading 'name')
```

这看起来像"工程坏了"，其实只是**没有活动文档**。工程树里有 Board1/PCB1，双击对应条目打开后 API 才正常。

### 复现路径与正确姿势

```text
1. 所有工程 → 单击目标工程行（等 0.6s，让选中生效）
2. 双击同一行
3. 轮询 target 列表，按 url 含 #id=<工程id> 匹配，最多等 10s
4. 连上后先点“工程”导航 → 双击 PCB/Schematic 条目打开文档
5. 确认 dmt_Board.getCurrentBoardInfo() 能返回再继续
```

### 附带发现

- 工程树每一行是 `div.tree-content`，`data-itemid` 就是工程 id，可直接用来拼 `https://pro.lceda.cn/editor#id=<id>`
- 行上的 `<a href>` 只出现在"已选中"的那一行，别拿它当通用方案
- `window.electronAPI.openWindow(url)` 调用返回 `undefined`、不产生新窗口（试过字符串、对象、带标题三种形状），**不能用来开工程**

## 工程树的正确定义：加号展开、双击载入当前窗口

用户纠正后实测确认，这两条是工程树的标准交互，应作为默认做法。

### 一、加号展开子项

`Board1` 行左侧（行矩形 `left + 10`）有一个展开控件。点击后子项出现：

```text
点击前：New Project / Board1(板) / Schematic1(原理图) / 1.P1(图页)
点击 (36,162) 后：… / Board1 / PCB1(PCB)
```

**注意**：子项 `PCB1` 默认是收起的，不点加号看不到。这也解释了我此前"树里找不到 PCB"的困惑。

### 二、双击标签 = 在当前窗口载入

实测（同一窗口，页数始终 4 个，不新开窗）：

```text
双击「图页: 1. P1」→ sch_PrimitiveComponent.getAll() 可用（comps=1），标签栏新增 P1.Schematic1
双击「PCB: PCB1」  → pcb_PrimitivePad.getAll() 可用（pads=4），标签栏保留 PCB1
```

标签栏最终为：`开始页 | PCB1 | P1.Schematic1`，两个文档并存、可来回切。

所以正确姿势是：

```text
1. 找目标行（entries 扫描，l 以 'PCB: ' / '图页: ' 开头）
2. 单击选中（等 0.4–0.5s）
3. 双击同一行
4. 用对应域的 API 自检（sch_* / pcb_* 能返回即成功）
5. 标签栏数量增加、窗口数不变
```

### 三、与 API 方式的关系

`dmt_EditorControl.openDocument(docUuid)` 也能开文档，但**它不改变窗口/标签状态**（`closeDocument` 同样返回成功却看不到效果）。所以：

- 要"界面上真的打开"，用双击树节点
- 要"后台拿文档句柄做批量操作"，用 `openDocument`

两者不冲突，但自检要以标签栏/域 API 为准，不能只看返回值。

### 四、此前误判的复盘

`notes/30` 里把"新工程打不开"归因为"双击无效 + 加载慢 + 标题不含工程名"，那部分对"打开工程（新窗口）"是成立的；但**同一工程内打开文档**这件事，我此前错在没点加号展开，导致树里看不到 PCB1，转而用 API 绕过。

正确顺序是：展开 → 看到子项 → 双击载入。
