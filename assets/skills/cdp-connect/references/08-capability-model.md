# 能力模型与实验结论总览

> 这一页回答两个问题：**这套东西现在能做什么、不能做什么**；**每条结论是在哪次实验里得到的**。
> 细节都在 `01`–`07` 合并卷里，本页只做判断与索引。

## 一、目标与判据

**目标不是"画完某个电路"**，而是获得一套换工程、换编辑器、换版本仍可用的操作能力。电路只是压力测试。

判据不看"做完了没有"，看这条能力是否**可重复、可验证、不依赖写死坐标**。

## 三、已验证的完整链路

### 原理图（从零到 ERC）

```text
Shift+N 建工程（新窗口需按标题跟随）
→ 放置 → 快捷器件（电阻/电容）→ 鼠标落位
→ getAll → modify({x,y,rotation}) 精确摆放
→ getAllPinsByPrimitiveId 取引脚绝对坐标
→ sch_PrimitiveWire.create(折线, net) + await done()
→ sch_Drc.check(true,true,true) 按 error/fatal 门禁
```

### PCB（从转换到 0 问题）

```text
设计 → 更新/转换原理图到PCB
→ pcb_Document.importChanges() → 对话框点「应用修改」
→ 按 1 mil 单位重排器件
→ MathPolygon.createPolygon + PrimitivePolyline.create("",11,poly,10) 画板框
→ pcb_Document.autoRouting({RoutingNets:[...]}) 只布指定网络
→ PrimitivePour.create(net, layer, poly) 建铺铜框
→ 选中 + 属性面板「重建铺铜区」或 Shift+B 灌注
→ PrimitiveVia.create(net,x,y,孔径,外径) 打缝合孔
→ pcb_Drc.check(false,true,true) → 0 问题
```

### 规则与区域（guideline 落地）

```text
pcb_Drc.getNetRules() → 改某网字段 → overwriteNetRules(整表)
pcb_PrimitiveRegion.create(layer, polygon, [2,5,7], 名称)   禁止元件/布线/覆铜
pcb_PrimitiveRegion.create(layer, polygon, [9], 名称)       约束区域
```

## 四、已知缺口（按严重度）

### 阻塞级（会挡住完整流程）

1. ~~**孤立铜区无法定位**~~ → **已解决**。DRC 每条问题都带 `pos` 与 `objs`，`pos` 就是问题坐标（1 mil）；在坐标附近补同网络过孔 + `Shift+B` 重建即可消除。实测 (100,-100) 补孔后 DRC 归零。`objs[0]` 是内部子对象 id，`Pour.get`/`Poured.get` 取不到，只能当线索。
2. **网络类无 API**。`NC_POWER`/`NC_DIFF_90R` 这类"类"只能走 UI；替代方案是逐网络写规则（`overwriteNetRules`），但与 UI 里的"类"不是同一数据。

### 受限级（能做但不可靠）

3. **`rebuildSingleCopper` 载荷未知**。消息名已抓到（`MSG_BUS_PCB` 上的 `rebuildSingleCopper`），但 `publish` 三种载荷都打不动，只能靠 `Shift+B` 或属性面板按钮触发。
4. **`sch_PrimitiveComponent.create` 挂死**。传组件描述符会 20 秒超时，放置只能"鼠标建 + API 定位"。
5. **DRC 偶发超时**。布线后立即 `check(strict=true)` 曾整 20 秒超时；改用 `check(false,true,true)` 稳定在 2–3 秒。
6. **面板计数不实时**。器件标准化改完数据后计数不动，刷新列表也不动；只能读组件字段。

### 未测（有能力但没跑）

7. 泪滴、扇出、蛇形等长、差分对布线、安装孔 NPTH、多层叠层与阻抗。
   （丝印文字与对齐已补齐：`pcb_PrimitiveString.create` 13 参已打通；对齐快捷键需「点画布拿焦点 → API 选中 → 发键」三步顺序。）
8. 跨工程/跨版本复验（C7）。
9. 放大器类器件（需器件库搜索且要过校验规则）。

## 六、三个可复用配方

### 配方 A：放元件并精确连线（原理图）

```text
快捷器件鼠标落位（位置随意）
→ getAll 找 designator
→ modify({x,y,rotation})
→ getAllPinsByPrimitiveId 拿引脚
→ Wire.create([x1,y1,x2,y2,...], NET) + done()
→ 出图确认
```

### 配方 B：双层铺铜 + 缝合（PCB）

```text
两层各建一个 Pour（3 参数，内缩 20 mil）
→ 选中 + 「重建铺铜区」或 Shift+B
→ Poured 计数 = 2 即成功
→ 四角+中点打 GND 过孔（12/24）
→ DRC 0 问题
```

### 配方 C：按规范设规则（PCB）

```text
getNetRules() 拿全表
→ 按网名找到目标，改 Track/Via Size 等字段
→ overwriteNetRules(整表)
→ 回读确认
→ 失效时用备份数组回滚
```

## 七、执行纪律（从踩坑里长出来的）

1. 任何写操作前**记基线计数**，写后对比。
2. 破坏性动作先在**单对象**上试。
3. 批量删除铺铜会卡进度条，**拆单个删**或删完等收敛。
4. 每次改动后**重建铺铜再跑 DRC**。
5. 判断"成功"的标准是**回读**，不是"点了没报错"。
6. 打桩（monkey patch）会污染 `toString`，**刷新页面才恢复**。
7. 单次实验只改**一个变量**，否则归因不了。

## 探查计划（能力导向，重立）

### 目标更正

之前把「画完 RC 振荡电路」当成目标，是错的。RC 电路只是**测试用例**，用来暴露操作面上的缺口。

真正的目标：**一套通用的立创EDA操作能力模型**——换工程、换编辑器类型、换客户端版本，agent 仍能找到控件、输入操作、判断状态、验证结果、出错回退。

判据也随之改变：不看「这个电路画完没有」，看「这条能力是不是可重复、可验证、不依赖写死坐标」。

### 能力矩阵（要填的表）

每一格都要有「怎么做到」和「怎么证明」，只有一条路径不算成立。

| # | 能力 | 要回答的问题 | 合格判据 |
|---|---|---|---|
| C1 | 发现 Discovery | 界面改版后，怎么重新找到某个功能 | 四条路至少两条通：菜单 / 快捷键表 / 命令名 / 界面搜索框 |
| C2 | 定位 Locate | 目标控件怎么点准 | 元素识别 + 可见性与遮挡判定 + `elementFromPoint` 命中校验 |
| C3 | 输入 Input | 画布类操作怎么落地（画布不可 DOM 点击） | 优先键盘命令，其次工具条，最后才坐标点击；命令通道必须打通 |
| C4 | 状态 State | 现在在哪个窗口 / 哪个编辑器 / 哪个图页 / 哪个模式 | frame 的 `entry=` + 图页树选中项 + 工具条可用态，三者互证 |
| C5 | 校验 Verify | 怎么知道操作真的生效 | DRC / ERC / 属性面板 / 网络表 / 计数变化，至少一种机器可读 |
| C6 | 回退 Recover | 操作错了怎么退回去 | 撤销栈、关闭重开、不保存原则；回退后能复核状态 |
| C7 | 泛化 Generalize | 换工程、换版本还成立吗 | 至少两个不同工程验证；记录版本指纹；不写死坐标与绝对路径 |

### 阶段重排

| 阶段 | 内容 | 主要填的格子 |
|---|---|---|
| P1 | 只读侦察：右键矩阵、设置遍历、快捷键表 | C1、C2 |
| P2 | 页面类型普查：每种编辑器的结构 + 定位方式 | C2、C4 |
| P3 | 元件标准化：编号分配流程 | C3、C5 |

### 用例的定位

RC 振荡电路不是目的，是**压力测试**：它同时踩到模拟电路、参数计算、原理图、PCB 布局、铺铜、走线、DRC，覆盖面广。

除此之外还要补两个不同工况且的用例，否则能力模型是偏的：

- **仿真页用例**：跑一次瞬态分析，看波形出在哪里（补 C5 的机器可读校验）
- **官方示例的三个 FPC / 3D 工程**：FPC 补强、金手指、3D 外壳是完全不同的编辑器和工具栏，正好检验 C1/C7——换一类编辑器，发现路径是否还成立

### 每条能力的记录格式

后续每条发现都按这个格式落盘，避免写成「我点了这里」这种一次性的记录：

```text
能力：C3 输入
场景：在原理图画布上改一个电阻的阻值
做法：选中元件 → 打开属性面板改值；或键入 A<space>value
判据：属性面板显示新值，且 ERC 无新增错误
限制：画布元件不可 DOM 点击，必须靠坐标或命令
证据：截图 + 属性面板文本 + 版本指纹
```

### 执行纪律

- 先验证「发现路径」，再记录具体坐标。坐标是证据，不是方法。
- 任何结论至少在一个额外工程复验一次，否则标「单点验证」。
- 换版本后先跑版本指纹，结构对不上就以新结果为准，不沿用旧笔记。
