# 客户端自重启：哪些设置会重启、重启后什么会失效

连接层见 `SKILL.md`，启停脚本与常驻入口见 `@references/launcher.md`。本篇只讲一件事：**客户端会在什么情况下自己重启，以及重启前后该做什么**。

写这篇的原因很实际：客户端会**在没有提示的情况下自己退出再拉起**。表现出来是「界面闪一下、回到开始页」，而 CDP 端点可能就没了。不提前知道，就会把「设置生效导致的正常重启」误判成「客户端崩了 / 端口又没开」，然后白折腾一轮。

## 一、先分清两类「重来」

| | 进程重启 | 页面重载 |
|---|---|---|
| 判据 | 主进程 pid 变了，`/json/version` 会短暂 404 | pid 不变，`/json/version` 全程可用 |
| 谁触发 | 设置变更、清理缓存、导入激活文件、客户端升级 | 菜单里的刷新、部分文档级设置 |
| 启动参数 | `app.relaunch()` 两条通道保留（见第三节），升级安装全丢 | 无关（不重新读命令行） |
| 端点 | 端口要重新绑定；绑不上就静默没有 | 一直可用，只有 page target id 变 |

两类都会让**下面这些现场全部作废**：

- page target id、`webSocketDebuggerUrl`
- 渲染层的 `windowId`（每次页面加载重新生成）
- 撤销栈（重启和重载都会清空）
- 文档的打开状态与脏标记

所以「重启前先把能保存的都存了」不是客气话：撤销栈没了，就只剩保存与不保存两个选项。

## 二、会触发进程重启的入口

代码证据来自 `resources/app/app.js`（客户端 V4.1.78，`app.js` 3.2 MB 未压缩，可直接 grep）。

| 入口 | 主进程做了什么 | 参数能活下来吗 |
|---|---|---|
| 设置里改**运行模式**（`ONLINE` / `HALF_OFFLINE` / `OFFLINE`） | 写 `config.json` → 清 service worker → `app.relaunch()` → `app.exit(0)` | ✅ 保留 |
| 设置里改**工程路径 / 库路径 / 在线备份路径 / 临时备份路径 / 日志级别 / 代理** | 同一个 `changeLaunchType` 处理器，同上 | ✅ 保留 |
| 设置 → 其他设置 → **清除缓存** | 清缓存 → 内部 `Ju()` 拉起新实例 → `app.exit(0)` | ⚠️ 只保留**第一个**参数 |
| 激活页**导入激活文件**（`/editor` + `entry=regist` 的 POST） | 把激活文件复制到位 → `app.relaunch()` → `app.exit(0)` | ✅ 保留 |
| **客户端升级安装**（`update/install`） | 拉起下载好的安装包 → 退出 | ❌ 全新进程，全丢 |
| 扩展 API `SYS_HeaderMenu.removeSystemHeaderMenuItem` | 不重启进程，但**菜单项只在重启后恢复**（官方文档明写） | — |

两个容易踩的细节：

1. **`changeLaunchType` 无论值有没有变都会重启。** 它内部算了「是否真的变了」的标记，但后面没拿它做分支——写配置、清 service worker、`app.relaunch()` 是无条件的。所以不要为了「读一下当前模式」去调它，也不要反复点同一个选项。
2. **它会顺带清 service worker**（`clearStorageData({storages:['serviceworkers']})`）。重启后首屏要重新拉资源，弱网下会明显变慢。重启后那几十秒白屏是正常现象，别急着判定端口坏了。

## 三、参数在两个重启通道里活得不一样

这是本文最有用的一条。客户端有两条拉起新进程的路径，传参方式不同：

| 通道 | 代码 | 传给新进程的参数 |
|---|---|---|
| 标准重启 | `app.relaunch()`（Electron 默认 `args = process.argv.slice(1)`） | 全部保留 |
| 清理缓存 | `Ju()`：`spawn(process.argv[0], [process.argv[1], ...])` | **只有 `process.argv[1]`** |

推论，直接决定启动脚本怎么排参数：

- **`--remote-debugging-port` 必须排在第一个。** 排第一，清理缓存那条通道也能把端口带过去；排在后面就丢了。`lceda-connect cdp start` 按这个顺序传参。
- 不要传 `--remote-debugging-address`：部分客户端版本不识别它。实际监听地址由 Chromium 决定，启动后要在系统监听表确认只监听回环。
- 用 `--proxy-server` 显式指定的代理参数在清理缓存通道里会丢。重启后客户端回到「按系统代理走」，与 CLI 默认行为一致。
- **升级安装后参数全丢。** 升级完必须重新 `start`，`ensure` 也会如实报「进程在跑但没带端口」。

关于「Electron 默认 `args = process.argv.slice(1)`」这一句：它是 Electron `app.relaunch()` 的文档语义，属于**静态依据**，本文没有在真机上逐条复跑。要自己验证，按第六节做一次改运行模式的重启，重启后看 `status` 里还有没有端口与 pid 变化。

## 四、重启之后什么会失效

| 东西 | 进程重启后 | 页面重载后 | 说明 |
|---|---|---|---|
| 端点 | 重新绑定，可能绑不上 | 不变 | 见第五节 |
| page target id | 变 | 变 | 每次都重新 `targets`，别缓存 |
| `windowId` | 变 | 变 | 随页面加载重新生成 |
| 撤销栈 | 清空 | 清空 | 重启前没落的操作就是丢了 |
| 未保存的修改 | 丢 | 丢 | 在线模式重启后从服务器版本载入 |
| 已打开的文档 | 回开始页 | 保留当前文档 | 在线模式工程从云端重载 |
| 内存里的临时状态（选中、过滤、视口） | 全丢 | 全丢 | 见下 |

最后一行常被忽略：**重启后的板面是「刚打开」的状态**，选中为空、视口复位、过滤条件清空。凡是脚本里「先选好一堆图元，再调 API」的链路，跨重启就断了，必须重新采样。

## 五、端点没了的三种结局

重启期间 `/json/version` 会短暂不可用，这是正常的。给 30 秒窗口，然后按进程状态分三类：

| 现象 | 含义 | 处置 |
|---|---|---|
| 有端点 | 重启完成 | 重新 `targets` / `pick_page`，不要复用旧 id |
| 主进程在，命令行**带** `--remote-debugging-port`，端点不通 | 还在重启，或端口没抢到 | `ensure` 再等；持续不通就是端口竞态，彻底退出后 `start` |
| 主进程在，命令行**不带**该参数 | 这个实例是「不带端口」起来的 | 端口开不出来，只能保存后彻底退出再 `start` |

「端口没抢到」不是猜的：重启是先用 `app.exit(0)` 结束旧进程、再拉起新进程，旧进程释放监听有延迟。Chromium 绑不上端口时**只记一条警告就继续跑**，界面照常可用、CDP 静默缺失。这就是为什么 `status` / `ensure` 要读一次命令行里的开关：否则「进程在、端口没」这种情况无法区分成因。

**不要试图自动修复后两类。** 修复意味着杀进程，而杀进程会丢用户未保存的工程。脚本的边界是诊断 + 给命令，动手的是用户。

## 六、推荐的处置流程

事前：

1. 确认要改的设置属于第二节表里的哪一条。要重启的，先让用户保存全部工程。
2. 记下当前打开的工程与文档页签（重启后要重开）。
3. 别在同一个脚本里「改设置 → 立刻求值」：重启会掐断这次 CDP 会话。

事中：

```powershell
# 端点没了先让它自愈，不要直接 start（会撞单实例保护）
<输出目录>\lceda-cdp.ps1 ensure
```

`ensure` 的契约：没进程就按 `start` 起；有进程就等 30 秒；等到就报端点，等不到就分「带参数 / 不带参数」给出不同处置。**任何情况下都不会杀进程。**

事后：

1. `python scripts/lceda_cdp.py discover`（端口固定就是 9222，但 uuid 归属要重核）
2. 重新 `targets` → `pick_page`（旧 page id 必失效）
3. 重新打开文档、重新取 `windowId`
4. 需要版本指纹的，重跑 `python scripts/check_environment.py`
5. 任何依赖撤销栈的兜底逻辑，重启后一律按「不可用」处理

## 七、少触发几次

- 能走 API 的设置不要点 UI；必须重启的，攒到一起改，一次改完。
- 不要在一次会话里反复切运行模式：每次都是「重启 + 清 service worker + 首屏重拉资源」。
- 换运行模式会切换数据根目录（在线/半离线/全离线看到的是不同的工程集合），切之前确认工程已同步或导出。
- 客户端升级后必须重新 `start`；升级是从安装包拉起的全新进程，参数一定丢。
